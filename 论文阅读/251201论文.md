## Towards autonomous system: flexible modular production system enhanced with large language model agents
走向自治系统:灵活的模块化生产系统受大型语言模型代理而增强

event  IEEE ETFA 2023


### 核心目标
提出了一个三种技术融合的框架
- **大语言模型 (LLMs)**：作为“认知引擎”，负责理解和推理。
- **数字孪生 (Digital Twins)**：作为“信息桥梁”，连接虚拟与现实。
- **工业自动化系统 (Industrial Automation System)**：作为“执行实体”，负责实际生产。

目的是实现生产过程的智能规划（Intelligent Planning）和控制（Control），解决传统自动化系统僵化、难以应对突发或定制任务的痛点 。

工业自动化系统的改造
为了让AI能控制机器，作者首先对自动化系统进行了改造（Retrofit），将其能力封装成两种粒度的可执行接口 ：
- 底层：细粒度功能 (Fine-granular Functionalities)
    - 执行者：自动化组件（Automation Components，如机械臂的一个关节动作、夹爪的开合）。
    - 定义：这是最基础的原子动作，相当于人的“肌肉收缩”。
- 高层：粗粒度技能 (Coarse-granular Skills)
    - 执行者：自动化模块（Automation Modules，如整个数控机床、运输机器人）。
    - 定义：这是由多个底层功能组合而成的完整能力，例如“搬运工件”、“钻孔”，相当于人的“走路”或“拿水杯”。

数字孪生：
LLM无法直接看到或摸到机器，因此作者开发了一套数字孪生系统
- 注册接口 (Registering Interfaces)：它将上述物理层改造好的“技能”和“功能”接口注册在虚拟世界中，让AI知道有哪些能力可以调用 。
- 描述性信息 (Descriptive Information)：它包含了关于生产系统的详细文档和元数据 。这相当于给LLM提供了一本“设备操作手册”，让它通过阅读（Interpret）来了解机器是干什么的、该怎么用。


大语言模型：
是一个双层代理系统
为了实现从自然语言到机器指令的跨越，作者设计了两类代理 ：
- Manager Agent（管理者代理）：位于上层，负责宏观规划。
- Operator Agent（操作员代理）：位于下层（模块层），负责微观执行。
 第一阶段：由 Manager Agent完成。
- 输入：用户的自然语言指令。例如：“生产一个带有喷漆Logo的钢制铭牌” 。
- 获取上下文：Manager Agent 向数字孪生系统查询，获取当前工厂中所有可用模块的“技能（Skills）”列表。例如：存储模块的“取件”、运输机器人的“运输”。
- LLM编排：Manager Agent 将用户指令和技能列表结合，生成一个技能序列。包括两部分
  1. 第一部分（代码序列）：`((S1)-(T1)-(I1)-(T1)-(M2)...)`
  2. 第二部分(解释部分)：每个代码的出发点和送达点
    此时的输出是抽象的步骤，是一个字符串
***
生成的技能序列会被发送给制造执行系统（MES）。MES系统会解析这个序列，(例如 `["S1", "T1", "M1"]`）后，需要知道 `S1` 到底是谁的技能，以及去哪里调用它)依次找到负责执行每个技能的具体“操作员代理”，并向它们发起服务调用 。

第二阶段：底层拆解这一步由 Operator Agent 完成。
- 输入：来自上层的单个技能指令。例如：“将工件从存储模块运输到CNC模块” 。
- 获取上下文：Operator Agent（例如运输机器人的代理）向数字孪生查询该特定设备的“功能（Functionalities）”列表。这些是带有具体API接口的原子动作，例如：“移动并对接（move_dock）”、“加载（load）”、“卸载（unload）” 。
- LLM编排：Operator Agent 将技能指令拆解为一系列具体的功能调用序列，并填入具体的API URL。
    - 生成的序列示例：
        1. 调用 `.../move_dock` 移动到存储点；
        2. 调用 `.../load` 装载工件；
        3. 调用 `.../undock` 解除对接；
        4. 调用 `.../move_dock` 移动到CNC点... 。
