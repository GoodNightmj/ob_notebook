## 区分 chatbot、workflow、agent、multi-agent
### chatbot :对话机器人
本质是围绕对话输入，去生成回复
可以外接知识库，也可以有上下文记忆
### workflow：工作流
本质是按照预先设计好的固定步骤去工作
只要流程是固定的，就是workflow
### Agent：智能体
特点是有一个固定的目标，但是他不限制你过程怎么实现，这也是Agent和Workflow 的最大区别

### Multi-agent:多智能体系统
多个Agent分工协作，每个Agent有不同角色

## 理解 agent 的基本循环：observe -> think -> act -> observe
Agent 不是一次性回答问题，而是反复“观察环境—做判断—执行动作—再观察结果”，直到任务完成。

与chatbot 的区别是Agent 会根据中间结果动态决定下一步，而不是一开始就把答案写死，另一个区别我认为是agent是有多个步骤的，而chatbot只有一个步骤
与workflow的区别是中间的流程是不固定的，他能根据观察结果调整行动的循环系统
Agent = LLM 作为大脑，工具作为手脚，环境反馈作为眼睛


## 明白什么时候不该用 agent：任务可预测、流程稳定、普通脚本能解决时，agent 反而增加不确定性。

Agent 解决的是“不知道下一步该做什么”的问题；如果下一步早就确定，就不该用 Agent。或者说，如果你都能提前画出完整流程图，那基本不需要了

##  Building effective agents

workflow 和agent的区分就是
1. LLM 仅负责执行路径中的特定节点。
2. LLM动态决定后续要做什么

几种系统模式
1. 基础和线性模式
	1. 增强型大模型：给大模型加工具
	2. 提示词链：上一个的输出作为下一个输入，减少单一任务复杂度
2. 路由并行模式
	1. 路由分发：难和简单任务给不同模型
	2. 并行化：
		1. 分片：100个大模型同时处理100页文档
		2. 投票：一个大模型具体解决一个问题
3. 复杂交互模式
	1. evaluator-optimizer（评估优化模式）：引入自我纠错机制，适用于过程难，但是评估结果简单的我任务
	2. Orchestrator-workers（编排工作模式）：一个模型只负责派任务
	3. 完全自主的智能体

##  A practical guide to building agents
Agent 是代表用户独立完成任务的系统
一般什么时候需要Agent：
1. 复杂的决策制定：涉及细微判断、异常处理或上下文敏感决策的工作流（如客服退款审批）
2. 难以维护的规则： 规则集过于繁杂导致系统笨重、更新成本高且易出错的场景（如供应商安全审查）。
- ==严重依赖非结构化数据: 涉及解释自然语言、从文档提取含义或对话式交互的场景（如处理保险索赔）。==
Agent一般有三个组件
1. model
2. tool:数据工具，行动工具，编排工具
3. instruction


## 问题：我的场景为什么需要 agent，而不是普通 workflow
当前是workflow ，但是由于输入是自然语言，大模型输出则是FBD的文本化表达，我很难验证结果的正确性，并且错误有可能在使用大模型的两步中任何一步产生，同时也面对这功能块库不全等资料这种问题，给所有的功能块库又不太现实，所以使用agent来解决会更好


***
- 可验证性  
    workflow 里 LLM 输出文本化 FBD 后，很难判断对不对；agent 可以调用解析器、规则检查器、PLCOpen XML 生成器、OpenPLC 导入检查、甚至仿真/编译工具，对结果做自动验证。
- 错误定位  
    当前两步 LLM 都可能出错，但 workflow 往往只能看到最终结果。agent 可以保留中间状态，例如：
    - 控制叙述解析是否正确
    - taglist 是否完整
    - 功能块选择是否正确
    - 引脚连接是否类型匹配
    - interlock/alarm 是否遗漏  
        这样错误可以定位到具体阶段，而不是笼统地说“生成错了”。
- 功能块库不完整的问题
    不需要一次性把所有功能块库塞给模型。agent 可以按需检索：先识别需要哪些功能块，再去库里查对应规格。如果找不到，就标记为缺失、选择候选替代、或请求人工确认。
- 自我修复能力  
    workflow 通常是“一次生成”；agent 可以是：  
    生成 FBD → 校验失败 → 分析失败原因 → 局部修正 → 再校验。 
    这对 FBD 特别重要，因为很多错误是结构性错误，比如未绑定输入、错误引脚、信号类型不匹配、遗漏安全联锁等。
- 处理不确定性  
    自然语言控制叙述经常含糊。agent 可以在关键歧义处停止并提问，或者生成多个候选实现并说明差异；workflow 更容易在不确定时直接猜。
