


## 第2.6节 NFA转换为DFA：子集构造算法

在前面的章节中，我们已经详细地讨论了非确定的有限状态自动机（NFA）的结构及其特性，同时也明确指出：尽管NFA在描述语言的接受能力上与确定有限自动机（DFA）等价，但由于其状态转移的不确定性，不利于高效实现词法分析。因此，实际中往往需要将NFA转换成确定有限自动机（DFA）。本节就介绍实现这一转换的经典算法：**子集构造算法（Subset Construction Algorithm）**。

### 2.6.1 子集构造算法的核心思想

子集构造算法的核心思想在于：**将NFA的不确定性通过对状态子集的精确分析，转化为DFA的确定性。** 具体而言，该算法的主要工作是：

- 以NFA状态的**子集**作为DFA的**单个状态**；
  
- 通过对NFA状态集合整体的状态转移进行分析，确定DFA状态之间的确定性转移关系；
  
- 处理NFA中的 $ε$ 转换，以确保所有可能的状态转换都被包含进最终构建的DFA中。
  

简而言之，子集构造算法通过对NFA的运行进行“仿真”，精确模拟NFA在读取字符串时所有可能的状态转移，从而得到一个完全确定化的状态转换表（DFA）。

### 2.6.2 子集构造算法的基本步骤

子集构造算法一般分为以下几个步骤：

1. **确定初始状态的ε闭包：**  
    从NFA的初始状态出发，计算通过任意 $ε$ 转换所能到达的所有状态，形成DFA的初始状态集合。
    
2. **状态子集的扩展与转换计算：**  
    对于当前DFA的某个状态集合，分析其在每个可能输入字符下转移后的状态集合：
    
    - 首先计算当前集合中各状态在输入字符下的转移状态集合；
      
    - 然后对得到的集合再计算 $ε$ 闭包，获得完整的转移状态集合。
    
3. **递归重复子集的分析过程：**  
    将步骤2得到的新状态集合，若为新出现的状态集合，则加入待处理状态集合（工作表）中，并重复上述过程，直至没有新的状态集合出现。
    
4. **识别DFA接受状态：**  
    若某个状态集合中包含NFA的接受状态，则该集合所对应的DFA状态也为接受状态。
    

下面，我们将详细介绍各个步骤。

### 2.6.3 ε闭包的计算方法

在子集构造算法中，计算 $ε$ 闭包（ε-closure）是一个至关重要的环节。所谓 $ε$ 闭包，就是从某个给定状态出发，仅通过 $ε$ 转换所能到达的全部状态的集合。计算 $ε$ 闭包可以采用图的遍历算法，包括深度优先搜索（DFS）或广度优先搜索（BFS）。

以DFS算法为例，$ε$ 闭包的计算伪代码如下：

```pseudo
procedure epsilon_closure(s):
    closure ← {s}
    for each 状态 t，若存在ε边从 s 到 t:
        if t 不在 closure 中:
            closure ← closure ∪ epsilon_closure(t)
    return closure
```

该算法的复杂度为线性级别（与NFA中状态数量及 $ε$ 边数量有关）。

### 2.6.4 子集构造算法伪代码与解释

子集构造算法的伪代码如下所示：

```pseudo
procedure subset_construction(NFA):
    Q ← {}                        // DFA的状态集合
    worklist ← {}

    Q0 ← epsilon_closure(NFA的初始状态)
    Q ← Q ∪ {Q0}
    worklist.enqueue(Q0)

    while worklist 非空:
        current ← worklist.dequeue()
        for 每个输入字符 c in Σ:
            new_state ← {}
            for 状态 s in current:
                new_state ← new_state ∪ δ(s, c)
            new_state ← epsilon_closure(new_state)

            DFA转移函数[current, c] ← new_state

            if new_state 不在 Q 中:
                Q ← Q ∪ {new_state}
                worklist.enqueue(new_state)

    确定接受状态（包含NFA接受状态的子集）为DFA接受状态
    return 构造的DFA
```

在上述伪代码中：

- `Q` 表示最终DFA中包含的所有状态子集；
  
- `worklist` 是一个待处理状态集合的队列；
  
- 每一次迭代，算法取出当前待处理的状态集合（current），然后对每个可能的输入字符计算新状态集合（new_state），再对其进行 $ε$ 闭包计算；
  
- 如果新状态未曾出现过，则加入队列进行进一步处理，直至队列为空。
  

### 2.6.5 一个详细的算法实例分析

下面，我们详细分析一个具体实例，展示子集构造算法的完整过程。考虑以下正则表达式及其对应的NFA：

$RE:a(b|c)^*$

首先，NFA的结构由Thompson算法构造（如前所述），包含状态集合 ${\{N_1,..., N_8, N_9\}}$，其中：

- 起始状态为 $N_0$ ；
- 接受状态为 $N_9$ ；
- 包含多个 $ε$ 转换。

其有向图如下所示:

![image-20250513185838801.png](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/image-20250513185838801.png)


子集构造算法具体执行过程如下：

#### （1）初始状态计算：

- DFA初始状态 = $ε(N_0)$ = $\{N_0\}$；
- 记该集合为 $Q_0$，加入DFA状态集合及工作表。

| DFA工作集 | 集合元素  | 转移符 |
| :----: | :---: | :-: |
| $Q_0$  | $N_0$ | 起始集 |

#### （2）扩展过程（第一次扩展）：

- 对 $Q_0$ 考虑字符 $a$ 转移，得到，再$\{N_1\}$计算 $ε$ 闭包，得到 $\{N_1,N_2,N_3,N_4,N_6,N_9\}$；
- 标记为状态$Q_1$，加入DFA集合；
- 同时，因$Q_1$包含NFA接受状态$N_9$，故$Q_1$是DFA的接受状态。

| DFA工作集 |           集合元素            | 转移符 |
| :----: | :-----------------------: | :-: |
| $Q_0$  |           $N_0$           | 起始集 |
| $Q_1$  | $N_1,N_2,N_3,N_4,N_6,N_9$ | $a$ |

#### （3）扩展过程（第二次扩展）：

- 对 $Q_1$ 考虑字符 $b$ 转移，得到 ${N_5}$ ，$ε$ 闭包后为${\{N_3, N_4, N_5, N_6, N_8, N_9\}}$，记为状态$Q_2$ ；
-  $Q_2$ 亦为接受状态；
- 对$Q_1$考虑字符 $c$ 转移，得到${N_7}$，$ε$ 闭包后为，$\{N_3,N_4,N_6,N_7,N_8,N_9\}$, 记为状态$Q_3$；
- $Q_3$ 亦为接受状态。

| DFA工作集 |         集合元素          | 转移符 |
| :-------: | :-----------------------: | :----: |
|   $Q_0$   |           $N_0$           | 起始集 |
|   $Q_1$   | $N_1,N_2,N_3,N_4,N_6,N_9$ |  $a$   |
|   $Q_2$   | $N_3,N_4,N_5,N_6,N_8,N_9$ |  $b$   |
|   $Q_3$   | $N_3,N_4,N_6,N_7,N_8,N_9$ |  $c$   |

#### （4）进一步扩展（后续扩展与循环）：

- 继续对 $Q_2$ 和 $Q_3$ 分别考察输入字符的状态转换，发现新的状态集合已经出现过，不再新增状态；
- 例如，$Q_2$ 在字符 $b$ 上转移仍为$Q_2$，在字符 $c$ 上转移为 $Q_3$；
- 同理，$Q_3$在 $b$ 转移到 $Q_2$ ，在$c$转移回$Q_3$ ；
- 因此，算法逐渐终止。

| DFA工作集 |           集合元素            | 转移符 |
| :----: | :-----------------------: | :-: |
| $Q_0$  |           $N_0$           | 起始集 |
| $Q_1$  | $N_1,N_2,N_3,N_4,N_6,N_9$ | $a$ |
| $Q_2$  | $N_3,N_4,N_5,N_6,N_8,N_9$ | $b$ |
| $Q_3$  | $N_3,N_4,N_6,N_7,N_8,N_9$ | $c$ |

最终，DFA中包含的状态为 ${Q_0,Q_1,Q_2,Q_3}$，其状态转换是完全确定的，不含ε转换，且清晰定义了每个输入字符下的转移情况。

### 2.6.6 算法复杂性分析与应用评价

- **时间复杂性：**  
    子集构造算法最坏情况下复杂度为 $O(2^n)$，其中n为NFA状态数。然而，实际应用中，算法表现远优于最坏情况，一般为线性或接近线性复杂度。
    
- **空间复杂性：**  
    DFA状态空间理论上可达NFA状态集合的幂集规模，但实际中也远小于理论最大值。

尽管子集构造算法理论复杂度高，但实际应用时表现高效，能够广泛应用于编译器构造领域。

### 2.6.7 小结
