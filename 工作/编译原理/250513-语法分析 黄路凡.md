

## 第四章 语法分析

语法分析是编译器前端的重要阶段。在这一阶段，编译器负责检查源程序的结构是否符合所定义的程序设计语言的语法规则，并将源程序的文本表示转化成更易处理的中间数据结构，典型的是**语法树（Syntax Tree）**。

本章我们将深入研究语法分析相关的核心理论与方法，包括：

- 上下文无关文法（Context-Free Grammar）
  
- 自顶向下分析算法（递归下降、预测分析、LL分析）
  
- 自底向上分析算法（LR分析）
  

首先，我们在第4.1节中讨论**语法分析器的任务**，明确语法分析阶段所要完成的具体工作。

---

### 4.1 语法分析的任务

#### 4.1.1 语法分析的作用与位置

回顾一下编译器整体的结构，我们曾经提到，编译器是一种流水线结构的软件系统，典型的可分为前端、中端、后端：

- **前端**：负责源程序的分析，主要包括词法分析、语法分析、语义分析等。
- **中端**：负责中间代码的优化。
- **后端**：负责目标代码生成。

![image-20250516162954762.png](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/202505192213983.png)


在第四章中，我们专注于前端的**第二个阶段：语法分析阶段**。

在前面的章节中，我们已经详细研究了前端的第一个阶段——词法分析器（Lexical Analyzer）。词法分析器接收源程序文本，输出一个记号流（Token Stream）。而语法分析器的输入，正是来自词法分析阶段所产生的这个记号流。

我们通过下面的图再清晰地看一下这种关系：

![image-20250516163742254.png](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/202505192213452.png)

语法分析器的核心任务，就是根据特定语言的语法规则，检查输入的记号流是否符合语言的结构，并最终生成一个方便后续阶段处理的结构化数据——通常是语法树。

---

#### 4.1.2 语法分析的核心任务

语法分析器具体的任务可以归纳为以下两点：

1. **检查源程序语法的正确性**（语法检查）。
   
2. **构建程序的内部表示**（生成语法树）。
   

我们详细来看这两个任务。

**1. 语法检查**

语法分析器首先需要做的是对程序进行结构上的检查，以确定程序是否符合相应语言的语法规则。

我们以一个简单的示例程序片段来看：

```c
1: if ((x > 5) {
2:     y = "hello"
3: } else
4:     z = 1,
```

上面这个片段中含有多个语法错误，典型的语法分析器会报告类似以下的信息：

```
Syntax error at line 1: 缺少右圆括号 ')'
Syntax error at line 2: 缺少分号 ';'
Syntax error at line 4: 期待分号 ';'，却看到了逗号 ','
```

我们观察这些错误信息可以发现：

- 编译器的语法分析器能够精确定位错误的发生位置；
  
- 能够清晰地指出预期出现的符号和实际出现的符号，帮助程序员准确而快速地定位错误；
  
- 错误信息的质量直接影响程序员修正程序的效率。
  

程序员在开发过程中，实际上与编译器之间形成了一种互动的、不断迭代的过程：

- 程序员编写程序 → 编译器语法分析检查 → 报错 → 程序员修正程序；
  
- 循环以上步骤直至程序完全合法。
  

**2. 生成语法树**

当程序的语法正确时，语法分析器的第二个重要任务是将程序转化为一种便于后续处理的数据结构，这就是我们所说的**语法树**（或称为抽象语法树，Abstract Syntax Tree，简称AST）。

以一个合法的if语句为例：

```c
if (x > 5) 
    y = "hello";
else 
    z = 1;
```

通过语法分析之后，生成的语法树大致如下：
![image-20250516164300148.png](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/202505192214353.png)

从上图中可以清晰地看出：

- 语法树中每个节点明确代表了程序中的特定结构，例如if语句、表达式、赋值语句等等；
  
- 后续编译器的阶段（语义分析、中间代码生成）会基于这样结构化的树来进行进一步处理；
  
- 与单纯的文本字符串不同，语法树提供了程序结构的丰富语义信息，便于后续阶段的处理。
  

因此，可以说语法分析器是编译器前端的重要分界点：

- 在此之前，程序以纯文本形式出现；
  
- 在此之后，程序以结构化的树状形式表示。
  

---

#### 4.1.3 语法分析器的输入输出接口

清晰地定义语法分析器的输入输出接口，有助于我们更好地理解后续实现过程：

- **输入**：
  
    1. 记号流（来自词法分析阶段）
       
    2. 语法规则（Context-Free Grammar, CFG，通常隐含在分析算法中）
    
- **输出**：
  
    1. 抽象语法树（Abstract Syntax Tree, AST）
       
    2. 语法错误信息（Syntax Error Report）
       

这样我们就可以将语法分析器视为一个清晰的黑盒模块：

### 本节小结

在这一节中，我们明确了语法分析器在编译器中的位置及其核心任务：

- 检查程序的语法正确性并进行精确的错误报告；
  
- 构造语法树供编译器后续阶段进一步处理。
