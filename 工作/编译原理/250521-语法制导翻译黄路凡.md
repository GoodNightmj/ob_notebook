## 第六章 语法制导翻译

语法制导翻译是语法分析阶段的关键扩展，通过为文法规则附加**语义动作（Semantic Action）**，将语法分析与语义处理（如表达式求值、类型检查、代码生成）结合。以下将结合具体例子说明其核心思想与实现方式。

### 6.1 语法制导翻译的任务

传统语法分析仅判断程序是否符合语法规则，但编译器还需完成**类型检查、生成目标代码**等语义处理。

例如，对于表达式1+2，语法分析确认其结构合法后，需通过语义动作计算值 3，并生成对应中间代码。

因此，我们发现语法分析存在以下局限性：

- 无法检测语义错误（如类型不匹配）

- 缺乏代码生成能力

- 未构建可后续处理的中间表示

---

基于以上局限性，我们提出了语法制导翻译，它的核心目标是在语法分析阶段同步完成**语义检查**与**初步翻译**，为后续阶段提供结构化数据，主要包括：

- 类型检查与作用域管理

- 符号表构建与语义错误检测

- 中间代码/目标代码生成准备

经过以上分析，针对编译器前端的多阶段翻译流程的语法分析可以总结为下表：

|     阶段     |     输入     |       输出       |      核心任务       |
| :----------: | :----------: | :--------------: | :-----------------: |
|   语法分析   | 源代码记号流 |  抽象语法树AST   |      结构验证       |
| 语法制导翻译 |     AST      | 带注释AST+符号表 | 类型检查/作用域验证 |
|   语义分析   |   注释AST    |     三地址码     |     结构化翻译      |

### 6.2 LR 分析中的语法制导翻译

首先先来回顾一下LR分析表，它的分析表结构主要由三部分组成：

- **Action表**：定义当前状态（S）和输入符号（T）对应的动作（如移进、规约、接受）。

- **Goto表**：记录状态（S）遇到非终结符（X）后的跳转状态（K）。

- **状态表示**：分析栈栈顶元素为当前状态（S），输入流指针为待处理符号（T）。

LR分析的规约操作流程可以分为四个步骤：

1. **触发条件**：当Action[S, T] = "Reduce I"时，按第I条规则规约。
2. **栈操作**：弹出右部对应的所有符号及状态，暴露新栈顶状态S'。
3. **状态跳转**：压入左部符号X，根据Goto[S', X]跳转到新状态K。

而语法制导翻译在LR分析的基础上增加了**语义动作执行**操作，即在符号弹出前执行操作$a_i$（如计算、赋值等）。

---

以计算表达式的值为例，现在有文法$G$:
$$
\begin{align*}
0 &: E \rightarrow E + E \\
1 &: \quad | \quad n
\end{align*}
$$
针对这种情况，我们在每个产生式后增加语义执行动作：
$$
\begin{align*}
0 &: E \rightarrow E + E,\quad a_0:{E=E_1+E_2}\\
1 &: \quad | \quad n, \quad\quad\quad a_1:{E=n}
\end{align*}
$$
在 Yacc 中，我们可以通过{}，\$\$ 以及 $x 来添加语义执行动作：
```yacc
// 表达式文法（简化版，仅含加法和数字）
exp : exp '+' exp { $$ = $1 + $3; }  // 归约时计算加法，$$为左部exp的值，$1，$3为右部exp的值
    | num         { $$ = $1; }       // 归约数字时，直接赋值为数字值
num : '0'         { $$ = 0; }        // 将字符'0'转换为数值0
    | '1'         { $$ = 1; }        // 将字符'1'转换为数值1
    | '2'         { $$ = 2; }        // 其他数字规则类似
```

那么当我们输入$1+2$ 时，会得到下列执行：

1. 词法分析：输出记号流 `num(1), +, num(2)`。
2. 语法分析与语义动作：
   - 归约`1`为`num`，`$$=1`。
   - 归约`2`为`num`，`$$=2`。
   - 归约`exp + exp`为`exp`，执行`$$ = $1 + $3 = 1 + 2 = 3`。
1. 输出结果：表达式值为 `3`。
### 6.3 **语法制导翻译实现原理**

上一节中我们结合了Yacc工具，通过算术表达式求值案例，讲解了语法指导翻译的基本思想。在本节中我们将深入探讨语法指导翻译的内部实现原理，重点分析自底向上（LR）分析技术的实现方案。

回顾一下语法制导翻译的核心思想: 

- 为每条语法规则的右部（产生式）附加**语义动作**，通常表现为代码片段（如类C语句）
- 特殊符号（如`$1`、`$2`）用于引用规则右部符号的值，需由工具（如Yacc）识别
- 执行时机在**右部分析完成并规约**时触发语义动作

---

我们先来分析一下语法制导翻译在LR分析上的核心修改点:

1. 在LR分析算法的**规约操作前**，插入语义动作执行逻辑。
2. 需访问分析栈中符号的值（如`$1`、`$2`等），用于语义计算。

因此, 为了能够访问分析栈中符号的值, 我们需要到分析栈的结构进行扩展, 将原先分析栈中的二元组扩展为三元组 `(symbol, value, state)`, 其中value符号对应的语义值（如数值、内存地址等）

---

接下来我们通过一个例子来说明其具体原理：

有文法G, 添加的语义动作是以Yacc语法来写的：
$$
\begin{align*}
0 &: E \rightarrow E + E,\quad {\$\$=\$1+\$2}\\
1 &: \quad | \quad n, \quad\quad\quad {\$\$=\$1}
\end{align*}
$$
首先我们可以画出这段文法的状态机：
![image.png](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/202505291359811.png)
我们以$7+8+9$作为输入处理示例，初始栈状态为$(S,\_,0)$

第一步移进7，此时栈的栈的状态如下表

|               步骤                |                操作                 |                       栈状态                       |
| :-----------------------------: | :-------------------------------: | :---------------------------------------------: |
| $$\begin{align*}1\end{align*}$$ | $$\begin{align*}移进7\end{align*}$$ | $$\begin{align*}(7,7,1)\\(S,\_,0)\end{align*}$$ |

接着第二步规约$E\rightarrow n$, 在这一步中，在将7弹出栈前，执行了$\$\$=\$1$这条语义动作，再将规约后的状态入栈

|               步骤                |                操作                 |                       栈状态                       |
| :-----------------------------: | :-------------------------------: | :---------------------------------------------: |
| $$\begin{align*}1\end{align*}$$ | $$\begin{align*}移进7\end{align*}$$ | $$\begin{align*}(7,7,1)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}2\end{align*}$$ | $$\begin{align*}规约$E\rightarrow n\end{align*}$$ | $$\begin{align*}(E,7,2)\\(S,\_,0)\end{align*}$$ |

随后到读取到第二个 +之前的操作与上面类似，我们直接给出分析栈

| 步骤 |         操作         |                栈状态                 |
| :--: | :------------------: | :-----------------------------------: |
| $$\begin{align*}1\end{align*}$$ | $$\begin{align*}移进7\end{align*}$$ | $$\begin{align*}(7,7,1)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}2\end{align*}$$ | $$\begin{align*}规约E\rightarrow n\end{align*}$$| $$\begin{align*}(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}3\end{align*}$$ | $$\begin{align*}移进+\end{align*}$$ | $$\begin{align*}(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}4\end{align*}$$ | $$\begin{align*}移进8\end{align*}$$ | $$\begin{align*}(8,8,1)\\(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}5\end{align*}$$ | $$\begin{align*}规约E\rightarrow n\end{align*}$$ | $$\begin{align*}(E,8,4)\\(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |

此时再继续进行会出现移进规约冲突，我们此处规定保证加号需要左结合，因此先进行$E\rightarrow E\space +\space E$ 规约处理，而这个语法规则对应的语义动作 $\$\$=\$1+\$2$, 其中$\$1$就是栈中的7，$\$2$是栈中的8

| 步骤 |                 操作                 |                栈状态                 |
| :--: | :----------------------------------: | :-----------------------------------: |
| $$\begin{align*}1\end{align*}$$ | $$\begin{align*}移进7\end{align*}$$ | $$\begin{align*}(7,7,1)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}2\end{align*}$$ | $$\begin{align*}规约E\rightarrow n\end{align*}$$| $$\begin{align*}(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}3\end{align*}$$ | $$\begin{align*}移进+\end{align*}$$ | $$\begin{align*}(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}4\end{align*}$$ | $$\begin{align*}移进8\end{align*}$$ | $$\begin{align*}(8,8,1)\\(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}5\end{align*}$$ | $$\begin{align*}规约E\rightarrow n\end{align*}$$ | $$\begin{align*}(E,8,4)\\(+,+,3)\\(E,7,2)\\(S,\_,0)\end{align*}$$ |
| $$\begin{align*}6\end{align*}$$ | $$\begin{align*}规约E\rightarrow E\space +\space E\end{align*}$$ |$$\begin{align*}(E,15,2)\\(S,\_,0)\end{align*}$$ |

之后的$+9$ 留作练习供你来完善分析栈表格。

通过两者对比，抽象语法树与传统分析树它们应该有一下区别：

|   **特征**   |      **分析树**      |   **抽象语法树（AST）**   |
| :--------: | :---------------: | :----------------: |
| **信息完整性**  | 包含完整推导过程（如优先级、括号） | 仅保留语义关键信息（运算符、操作数） |
|  **节点冗余**  |   含非必要节点（如括号符号）   |    剔除不影响语义的语法细节    |
|  **存储效率**  |      节点和边较多       |    精简结构，降低内存占用     |
| **编译器关注点** |      编码语法规则       |  聚焦程序语义（如表达式计算逻辑）  |

---

而两者之间的差异性，实际上也是**具体语法**和**抽象语法**的差异：

- **具体语法**是语法分析器使用的语法，它作为语法分析器输入，需满足分析算法要求，消除语法的二义性
- **抽象语法**是编译器内部表示，它接近自然语言的简化形式，允许保留语义二义性

#### 6.4.1 抽象语法树数据结构

在编译器中，为了定义抽象语法树，需要使用实现语言来定义一组数据结构，接下来我们以C语言为例，来看看C语言版的抽象语法树数据结构。

我们以下面的这个文法为例：
$$
\begin{align*}
E \rightarrow E + E \\
\quad | \quad E * E\\
\quad | \quad n
\end{align*}
$$
**枚举类型定义：**

```C
typedef enum {EXP_INT, EXP_ADD, EXP_MUL} NodeKind;
```

**结构体设计：**

```C
typedef struct {
    NodeKind kind; // 固定为EXP_INT(0)
    int n;         // 整数值
} ExpInt;

typedef struct {
    NodeKind kind; // 固定为EXP_ADD(1)
    struct ExpNode* left;  // 左操作数
    struct ExpNode* right; // 右操作数
} ExpAdd;

typedef struct {
    NodeKind kind; // 固定为EXP_MUL(2)
    struct ExpNode* left;  // 左操作数
    struct ExpNode* right; // 右操作数
} ExpMul;
```

**构造函数实现：**

```C
ExpNode* ExpInt_new(int n) { //整形数节点构造
    ExpInt* p = (ExpInt*)malloc(sizeof(ExpInt)); //分配`ExpInt`结构体内存
    p->kind = EXP_INT;
    p->n = n; //赋值整型参数`n`
    return (ExpNode*)p;
}

// 运算符节点构造（加法）
ExpNode* ExpAdd_new(ExpNode* left, ExpNode* right) {
    ExpAdd* p = (ExpAdd*)malloc(sizeof(ExpAdd));
    p->kind = EXP_ADD;
    p->left = left;
    p->right = right;
    return (ExpNode*)p;
}

// 运算符节点构造（加法）
ExpNode* ExpMul_new(ExpNode* left, ExpNode* right) {
    ExpAdd* p = (ExpAdd*)malloc(sizeof(ExpMul));
    p->kind = EXP_MUL;
    p->left = left;
    p->right = right;
    return (ExpNode*)p;
}
```

---

在给出了上面的抽象语法树实现后，我们通过$2+3*4$手工构造抽象语法树的方式来说明一下整个过程。

整个表达式共有五个符号，因此共需要五条代码来构造整个表达式

```C
e1 = ExpInt_new(2);
e2 = ExpInt_new(3);
e3 = ExpInt_new(4);
e4 = ExpMul_new(e2, e3);
e5 = ExpAdd_new(e1, e4);
```

首先来看前3条代码，这三条代码分别构造以下三个节点：

![image-20250527165912657](https://raw.githubusercontent.com/GoodNightmj/PicGo/master/202505291401067.png)

e4通过e2与e3节点创建了一颗子树，e5再通过e1和e4节点再创建出了最后的语法树：

void pretty_print (e){
    switch (e->kind) {

#### 6.4.2 抽象语法树的自动生成

对于抽象语法树的自动生成，我们的思路主要如下：

- 在语法动作中，加入生成语法树的代码片段，这个片段一般是语法树的“构造函数”
- 在产生式规约时，会自底向上构造整棵树

还是以下面这个例子为例：
$$
\begin{align*}
E \rightarrow E + E \\
\quad | \quad E * E\\
\quad | \quad n
\end{align*}
$$
针对上面这个文法，我们在每个文法规则后面添加如下语义动作：
$$
\begin{align*}
E \rightarrow E + E \quad\{\$\$\space=\space ExpAdd\_new(\$1,\$3);\}\\
| \quad E * E\quad\{\$\$\space=\space ExpMul\_new(\$1,\$3);\}\\
\quad | \quad n\quad\{\$\$\space=\space ExpInt\_new(\$1);\}\quad\quad\quad
\end{align*}
$$
其中三个构造函数是我们在上一节中所编写的构造函数。

---

而在我们使用生产级编译器时会发现，当编译出错时通常会打印出错误信息，为了说明如何对语法分析树的信息进行拓展，我们以位置信息为例来说明如何修改抽象语法树的数据结构。

假设有一段$2+3+4$的代码存储在文件$a.c$中，由于程序都存储在文件中，因此我们首先就可以定义一个描述位置的结构体：

```C
struct position_t {
	char *file;  // 源文件句柄
    int line;    // 行号
    int column;  // 列号
};
```

而对于加号结构体，只需要增加两个位置结构体就可以

```C
struct Exp_Add {
  enum kind kind;
  Exp *left;
  Exp *right;
  struct position_t from;
  struct position_t to;
};
```

通过from和to变量，我们就可以知道这个语法树所对应的位置。
