**9.1.1中间代码的地位和作用1**

   从本章开始，我们将共同开启一个全新的专题——中间表示及其在程序分析中的应用。作为这一部分的开篇，我们将着重探讨中间表示（中间代码）在编译器中的重要地位与作用，剖析其为何在编译器设计中不可或缺，以及它能为我们带来哪些关键优势。

   首先，让我们回顾一下编译器的前端工作。编译器前端作为一个整体模块，其输入是源程序代码，并通过词法分析、语法分析、语义分析等多个阶段的处理，最终输出中间表示。这就好比一个复杂的加工厂，将原材料（源代码）经过一系列工序打造成半成品（中间表示），为后续的进一步处理做好准备。在之前的章节中，我们已经对抽象语法树有了较为详细的了解。抽象语法树作为程序的一种内部表示形式，它直接反映了源代码的结构，是编译器前端输出的一种形式，也是我们后续中间表示研究的起点。

   如果我们将目光投向一个最简单的编译器结构，可以发现其流程大致如下：从抽象语法树出发，经过一个翻译过程（也可称为代码生成），直接生成目标体系结构的汇编代码。最终，可执行程序由此诞生。这种简单结构的特点在于，中间表示仅有抽象语法树一种形式，它直接被翻译成目标代码，无需额外的中间转换。但现实中，现代编译器的结构远比这复杂得多。一般来说，现代编译器从抽象语法树开始，先完成类型检查，确保无误后，将其作为输入，经过第一个翻译过程生成第一个中间表示。随后，这一中间表示又会成为第二个翻译过程的输入，进而生成第二个中间表示。如此层层递进，经过多个中间表示的转换，最终才生成汇编代码。不同的编译器设计在中间表示的选择和使用上存在差异，但万变不离其宗的是，它们都在追求更高效、更优化的代码生成。

   接下来，让我们从宏观角度对常见中间表示进行一个概览。首先是树和有向无环图（DAG）。抽象语法树作为树状结构的代表，它为程序源代码提供了一种直观且高效的表示方式。因为源代码通常基于上下文无关文法构建，而上下文无关文法的典型结构正是树状的，所以抽象语法树能够精准地映射源代码的语法结构，为后续处理提供便利。紧接着是三地址码，这是一种相对低层的中间表示形式，与高层的树状结构相比，它更接近目标机器。以 RISC 机器为例，其操作常遵循类似 “add X, Y, Z” 的模式，即将 Y 和 Z 的值相加后赋给 X。这种操作中涉及三个操作数，即三个地址，因此得名三地址码。其特点是每个操作都相对原子化，仅完成少量计算，避免了复合操作的复杂性。这使得三地址码更贴近机器指令，便于后续优化处理。

   再往后是控制流图（CFG）。控制流图可以被视为一种更为精细的三地址码表示，它以图状结构呈现程序，直观地展示程序的控制流。相较于传统的线性代码表示，控制流图使程序的分支、循环等控制结构一目了然，为控制流分析和优化提供了强有力的支持。在现代编译器中，控制流图的应用十分广泛，尤其是在程序分析和优化阶段，它几乎成为必不可少的工具。

   此外，还有静态单赋值形式（SSA）。SSA 是控制流图的一种精细化扩展，它不仅编码了控制流信息，还能编码数据流信息。这种双重信息编码能力使 SSA 成为一种高效紧凑的中间表示形式。从 20 世纪 80 年代末 90 年代初诞生以来，SSA 凭借其优越的特性迅速获得了广泛关注，并被现代编译器（如 GCC 4.0 及其后续版本）普遍采用，作为中间表示及优化框架的核心。

   最后提及的连续传递风格（CPS），它是函数式语言中较为常用的一种中间表示。CPS 可以视为 SSA 的一种更通用形式，它能够表达跨函数、跨模块的控制跳转，突破了 SSA 通常局限于函数内部的限制。

   以上列举的中间表示形式仅为冰山一角。在实际的编译器设计实践中，各种中间表示层出不穷，每个编译器所采用的中间表示都有其独特之处。然而，它们背后蕴含的通用设计思想和成功的实践经验却具有共通性。我们在此列出这些经典且基本的中间表示形式，旨在为后续的深入研究奠定基础。它们不仅是现代编译器中普遍使用的工具，更是我们接下来学习和研究的重要内容。

**9.1.3中间代码的地位和作用3**

   在编译原理的学习进程中，本部分将系统性地剖析中间表示的相关理论与技术。我们的目标是深入探究中间表示在编译器设计中的核心问题，并提供相应的解决方案。

   首先，将详细介绍现代编译器中常用的多种中间表示形式。这些形式是编译器设计与实现过程中的关键组成部分，也是理解编译器工作原理的基础。具体来说，我们将深入探讨三地址码、控制流图以及静态单赋值形式（SSA）。三地址码以其简洁的指令形式，便于编译器进行优化处理；控制流图通过直观的图示结构，清晰展现了程序的执行流程；而 SSA 则以其强大的数据流分析能力，成为现代编译器优化的主流选择。这几种中间表示形式，是编译器设计中经过长期实践验证的经典方案，在不同的编译器实现中广泛存在，对编译器的性能和效率起着决定性的作用。

  其次，书中将着重介绍在中间表示基础上进行程序分析的理论与技术。程序分析是编译器优化的关键环节，它能够为代码优化提供必要的信息支持。在中间表示上开展程序分析，能够充分利用中间表示的优势，深入挖掘程序的潜在特性。我们将重点研究两类重要的程序分析方法：控制流分析和数据流分析。控制流分析关注程序的执行顺序和转移逻辑，通过分析控制流图等中间表示，可以识别循环结构、基本块等关键概念，为优化编译器的控制结构提供依据。数据流分析则侧重于程序中数据的传播与使用情况，通过收集数据流信息，能够为编译器的优化决策提供丰富的数据支持。

   通过本部分的学习，全面了解中间表示的理论基础、技术细节以及在编译器中的实际应用。这将为后续深入研究编译器的代码优化技术，构建高效的编译系统奠定坚实的基础，帮助读者在编译器设计领域迈出关键的一步，开启深入探索的大门。

**9.2.1三地址码1**

   在编译器设计中，前端负责生成中间表示。中间表示是编译器对源代码进行处理后得到的一种内部表示形式，它是连接编译器前端和后端的桥梁。三地址码作为一种重要的中间表示，其生成过程起始于抽象语法树。抽象语法树是对源代码的结构化表示，而三地址码则是通过一系列翻译过程从抽象语法树生成的。这一过程通常由语义分析器负责，除了进行语义检查外，它还承担着生成中间表示的任务。当然，在实际实现中，也可以设计一个独立的模块来遍历抽象语法树以生成中间表示。

   最简单的编译器结构可能是直接从抽象语法树生成汇编代码。然而，当引入三地址码后，编译过程会发生变化。首先，从抽象语法树出发，经过一个翻译过程生成三地址码这一中间表示。然后，三地址码再作为输入传递给后续的翻译模块，最终生成汇编代码。这表明，在采用三地址码作为中间表示的编译器中，整个编译流程相较于最简单结构增加了一个中间环节。

   三地址码的设计理念与底层机器结构非常相似。它为每个中间变量和计算结果分配一个临时名称，从而消除了复合表达式。这样，程序中的每个操作都被分解为原子操作。在控制流方面，三地址码仅保留最基本的控制结构，如条件跳转、无条件跳转、函数调用和返回等，而将源程序中的高级控制结构（如 `do`、`while`、`for` 等）转换为等价的基本控制结构。因此，三地址码可以被视为一种抽象的机器指令集，它与目标机器非常接近，但并未绑定到具体的机器指令上。这种特性使得三地址码具有通用性和抽象性，类似于一个抽象的 RISC 指令集。

**9.2.2三地址码2**

以下是一个 C 语言程序片段及其对应的三地址码表示：

    A = 3 + 4 * 5;
    if (x < y) {
        z = 6;
    } else {
        z = 7;
    }

**三地址码表示：**

    X_1 = 4
    X_2 = 5
    X_3 = X_1 * X_2    // 计算 4 * 5
    X_4 = 3
    X_5 = X_4 + X_3    // 计算 3 + (4 * 5)
    A = X_5             // 将计算结果赋值给 A
    cjmp X < Y, L1, L2  // 条件跳转，判断 x < y
    L1: Z = 6
        jmp L3
    L2: Z = 7
        jmp L3
    L3:

   在三地址码中，临时变量（如 `X_1`、`X_2` 等）由编译器自动生成，用于存储中间计算结果。通过这种方式，原本复杂的复合表达式被分解为多个简单的原子操作。例如，赋值语句 `A = 3 + 4 * 5` 被分解为多个步骤：首先计算 `4 * 5` 并将结果存储在临时变量 `X_3` 中，然后计算 `3 + X_3` 并将结果存储在 `X_5` 中，最后将 `X_5` 的值赋给 `A`。对于条件语句，三地址码通过条件跳转指令（`cjmp`）和标号（`L1`、`L2`、`L3`）来实现不同分支的控制流。这种表示方式使得程序的结构更加清晰，便于后续的优化和代码生成。

**9.2.3三地址码3**

三地址码的语句形式类似于上下文无关文法，具体定义如下：

1. **常数赋值**：`X = N`，其中 `N` 为整型常量，`X` 为变量。

2. **二元运算**：`X = Y op Z`，其中 `op` 可代表加、减、乘、除等运算符，`Y` 和 `Z` 为变量。

3. **一元运算**：`X = op Y`，如取非、取负等运算。

4. **数据移动**：`X = Y`，表示将变量 `Y` 的值赋给变量 `X`。

5. **内存写入**：`*Y + Z = W`，表示将变量 `W` 的值写入到以 `Y` 为起始地址、偏移量为 `Z` 的内存位置。

6. **内存读取**：`X = *Y + Z`，表示从以 `Y` 为起始地址、偏移量为 `Z` 的内存位置读取值并赋给变量 `X`。

7. **函数调用**：`X = F(X1, X2, ..., Xn)`，表示调用函数 `F`，并将结果赋给变量 `X`，其中 `X1, X2, ..., Xn` 为变量。

8. **条件跳转**：`cjmp X, L1, L2`，表示根据变量 `X` 的值进行条件判断，若条件成立则跳转到标号 `L1`，否则跳转到标号 `L2`。

9. **无条件跳转**：`jmp L`，表示直接跳转到标号 `L`。

10. **标号定义**：`label L`，表示当前指令所在的位置为标号 `L`。

11. **函数返回**：`return X`，表示从函数返回，并将变量 `X` 的值作为返回值。

   在三地址码中，所有的运算对象均为变量，不存在复合表达式。这种定义方式确保了三地址码的原子性，便于编译器进行后续的优化和代码生成。

**9.2.4三地址码4**

   为了将三地址码的定义转化为数据结构，以便编译器能够以代码和算法的形式进行处理，可以对每个语句类型分配一个唯一的编号。例如，在表示一个加法运算时，需要为其指定一个特定的指令类型编号，并记录涉及的三个变量（如 `X`、`Y`、`Z`）。类似的编码方式也适用于数据移动指令等其他语句类型。这种编码过程与前面章节中介绍的内容相一致，具体的编码细节可以作为练习，供读者进一步思考和理解三地址码的定义。

   在生成三地址码的过程中，通常采用递归下降的代码生成算法。这一算法的基本原理与前面章节中介绍的代码生成过程相似，但目标是生成三地址码而非直接生成汇编代码。以扩展的 C-- 语言为例，其语法结构包括程序、函数、变量声明和多种语句类型（如函数调用、返回语句、条件语句和循环语句）。对于每一种非终结符，都需要编写相应的代码生成函数。以语句的代码生成为例，根据不同的语句类型（如赋值、打印、函数调用、返回、条件、循环等），编写相应的代码生成逻辑。例如，在生成赋值语句的代码时，首先递归生成右侧表达式的代码，并将结果存储在某个变量中，然后生成将该变量值赋给目标变量的指令。对于函数调用语句，则需要递归生成所有实际参数的代码，并将结果存储在临时变量中，最后生成函数调用指令。条件语句的代码生成则涉及到条件表达式的生成、条件跳转指令的生成以及分支代码的生成等步骤。

**9.2.5三地址码5**

三地址码具有以下特点和结论：

### 优点

1. **原子操作**：三地址码中的每个操作均为原子操作，不存在复合表达式。这使得每个操作都简单明了，便于理解和处理。

2. **简化控制流**：三地址码将复杂的控制结构简化为基本的控制流语句，如条件跳转和无条件跳转。这有助于简化编译器的设计和实现，提高编译器的效率和可靠性。

### 缺点

1. **控制流信息隐式表示**：在三地址码中，程序的控制流信息是以隐式的方式表示的。例如，从一个标号能够跳转到哪些其他标号等信息并不直观。因此，可能需要进一步的控制流分析来显式地表示这些信息，以便于后续的优化和代码生成过程。

### 代码生成

从三地址码生成汇编代码相对较为容易。由于三地址码本身已经非常接近底层机器代码，且消除了复合结构和高级控制结构，因此可以较为直接地将其转换为汇编代码。例如，在栈式计算机上生成汇编代码时，可以根据三地址码的每个指令生成相应的汇编指令序列。这可以作为练习，供读者进一步思考和实践。

综上所述，三地址码作为一种重要的中间表示形式，在编译器设计中具有关键作用。它的原子操作和简化控制流的特点使其成为连接编译器前端和后端的理想中间表示。尽管存在控制流信息隐式表示的不足，但通过适当的分析和处理，可以克服这一问题。通过学习和理解三地址码的定义、生成和应用，读者可以深入掌握编译器设计中的核心技术和方法。

**9.3.1控制流图1**

控制流图（Control Flow Graph，CFG）是另一种重要的中间表示形式。在编译器的前端处理过程中，源程序首先被翻译成一个中间表示，例如抽象语法树，然后经过一系列的翻译步骤生成中间表示。在之前的讨论中，我们已经看到三地址码作为中间表示的应用实例：从抽象语法树出发，经过翻译生成三地址码，再最终生成汇编代码。类似地，控制流图也可以作为编译器中的中间表示使用。一种典型的编译器结构是：从抽象语法树出发，先生成三地址码，然后再将三地址码翻译成控制流图，最后由控制流图生成汇编代码。需要强调的是，不同编译器在中间表示的选择和使用上存在差异。有些编译器可能直接从抽象语法树生成控制流图，跳过三地址码这一中间步骤。这种设计选择取决于编译器的具体架构和优化需求。

控制流图的引入主要是为了解决三地址码在表示程序控制流方面的不足。例如，在三地址码中，标号（如 L1、L2）的跳转关系是隐式的，需要通过扫描整个代码来确定跳转来源。相比之下，控制流图以图形化的方式明确展示了程序的控制流结构。在控制流图中，节点代表基本块（Basic Block），基本块是一组连续的语句序列，只能从入口进入，从出口退出，中间不会出现跳转。边则表示基本块之间的跳转关系。通过将程序表示为有向图，控制流图能够直观地展示程序的执行路径和控制逻辑。例如，在判断有多少条指令可以跳转到某个标号（如 L2）时，控制流图可以通过计算节点的入度来快速得出结论，而无需逐一扫描代码。这种直观的图形化表示为后续的程序分析和优化提供了便利。

**9.3.2控制流图2**

控制流图的基本概念如下：

1. **基本块（Basic Block）**：基本块是控制流图中的基本单位，它是一组连续的语句序列，从第一个语句开始执行，直到最后一个语句执行完毕。基本块内部没有跳转入口或出口，所有跳转语句（如条件跳转、无条件跳转）只能出现在基本块的末尾。

2. **控制流图（Control Flow Graph, CFG）**：控制流图是一个有向图 G = (V, E)，其中 V 是节点的集合，E 是边的集合。节点代表基本块，边代表基本块之间的跳转关系。

举个例子，假设有一个基本块 L2，它包含若干条语句，只能从第一个语句进入，从最后一个语句退出。基本块之间通过边连接，表示控制流的跳转。例如，从基本块 L2 跳转到基本块 L3，可以通过在 L2 的末尾添加一条跳转边来表示。控制流图通过这种方式详细地描述了程序的控制流逻辑。

控制流图的上下文无关文法定义可以看作是三地址码的一种精细化表示。它包含了三地址码中的各种语句形式（如赋值、二元运算、数据移动、函数调用等），以及跳转语句（如无条件跳转、条件跳转、返回语句等）。基本块由标号（Label）、若干条语句和一个跳转语句组成。一个函数由多个基本块构成，其中包含入口块和出口块。入口块是函数开始执行的第一个基本块，出口块是包含返回语句的基本块。

通过这种方式定义的控制流图，不仅保留了三地址码的语义信息，还进一步明确了程序的控制流结构。这种精细化的表示为后续的程序分析和优化提供了坚实的基础。

**9.3.3控制流图3**

生成控制流图是编译器中间表示转换的重要环节。根据编译器的设计不同，生成控制流图的方法也有所差异。以下是两种常见的生成控制流图的方法：

1. **直接从抽象语法树生成**：对于具有结构化控制流的语言（如 Java），可以直接从抽象语法树生成控制流图。这种方法适用于控制流结构较为规整的语言，能够直接映射高层语言的控制结构到控制流图中。

2. **从三地址码生成**：对于包含非结构化控制流的语言（如 C），通常先生成三地址码，再从三地址码生成控制流图。这种方法适用于复杂的语言结构，能够将高层语言的语法树转换为线性结构，再通过扫描生成控制流图。

本课程重点讨论第二种方法，即从三地址码生成控制流图。这种方法体现了编译器设计中的阶段划分思想，将复杂的编译过程分解为多个独立的阶段，每个阶段专注于特定的任务。具体来说，首先将源程序翻译成三地址码，然后再通过一个独立的模块将三地址码转换为控制流图。

生成控制流图的算法可以采用线性扫描算法。该算法的时间复杂度为 O(n)，其中 n 是三地址码语句的数量。算法通过一次线性扫描三地址码语句序列，识别基本块并构建控制流图。以下是线性扫描算法的伪代码描述：

    List_t stms = 三地址码语句列表
    list_t blocks = 空集合
    block b = 新建空基本块
    blocks 初始化为空
    
    foreach 语句 s in stms:
        if s 是标号：
            b.label = s
            blocks.add(b)
            b = 新建空基本块
        else if s 是跳转语句：
            b.jump = s
            blocks.add(b)
            b = 新建空基本块
        else:
            b.statements.add(s)

通过这种方法，可以高效地从三地址码生成控制流图，为后续的程序分析和优化提供支持。

**9.3.4控制流图4**

生成控制流图后，可以利用图论算法对程序进行深入分析。控制流图作为一种有向图，可以应用各种图论算法，如遍历算法、生成树算法、必经节点分析等。这些算法能够帮助编译器更好地理解程序的结构和行为，为优化提供依据。

一个典型的优化实例是死基本块删除（Dead Basic Block Elimination）。该优化通过识别不可达的基本块并将其从控制流图中移除，从而简化程序结构，提高执行效率。例如，考虑一个包含循环和 continue 语句的 C 语言代码片段。通过构建控制流图，可以发现某些基本块（如 L3）在程序执行过程中无法被访问。这些不可达的基本块被称为死基本块。死基本块的存在不仅增加了程序的代码量，还可能使控制流图变得复杂。通过死基本块删除算法，可以有效地移除这些无用的基本块及其相关的边，简化控制流图。

死基本块删除算法的步骤如下：

1. 使用深度优先搜索（DFS）遍历控制流图，标记所有可访问的节点。

2. 遍历所有节点，若某个节点未被访问，则将其及其出边从图中删除。

该算法能够显著减少控制流图中的节点和边的数量，降低后续分析和优化的复杂度。例如，在一个包含多个基本块的控制流图中，通过死基本块删除算法，可以将节点和边的数量从四个减少到三个，从而简化程序结构，提高执行效率。

综上所述，控制流图作为一种重要的中间表示形式，能够直观地展示程序的控制流结构，为程序分析和优化提供了强大的支持。通过线性扫描算法生成控制流图，并结合图论算法进行优化，可以显著提高编译器的性能和效率。

**9.4.1数据流分析1**

数据流分析是继控制流分析之后的又一类重要的程序分析方法。在编译器的设计中，中间表示扮演着关键的角色。从前文可知，编译器可以通过多次翻译将抽象语法树转换为控制流图等多种中间表示形式，最终生成汇编代码。然而，中间表示的数量和种类并无统一标准，这完全取决于具体的编译器设计。

数据流分析与优化紧密相关。优化的目标是提升程序的性能，如减小代码量、提高运行速度等。优化贯穿于整个编译流程，在不同的中间表示上均可实施。例如，现代编译器可能在中间表示一上进行优化改写，或在中间表示二上继续优化。实际上，优化不仅可以在中间表示上进行，在抽象语法树和汇编代码等其他表示上同样适用。现代优化编译器会在编译流程的各个阶段进行优化。

数据流分析为优化提供了必要的信息支持。在优化过程中，首先对程序进行分析，收集静态信息，然后利用这些信息指导程序的重写。重写过程可以生成相同或不同的中间表示。以 GCC 的 SSA 为例，优化后的中间表示仍为 SSA。优化过程通常分为两步：首先进行程序分析以收集静态信息，然后利用这些信息对程序进行重写。程序分析的类型多样，包括控制流分析、数据流分析等，旨在获取程序执行的静态保守信息。静态保守信息是对程序动态行为的近似或估计，有助于指导程序的优化改写。

**9.4.2数据流分析2**

理解静态保守概念对掌握数据流分析至关重要。以一个包含四个基本块的控制流图为例，程序结构为典型的 if 语句。若要判断能否将变量 Y 替换为常量 3，需分析程序代码。若 Y 仅被赋值为 3，那么在使用点 Y 的值始终为 3，此时可进行常量传播优化，提升程序效率。常量传播优化通过传播常量信息消除变量，减少多余赋值，在优化编译器中极为常见。

但在某些情况下，编译器可能无法确定程序的执行路径，如变量 X 的值影响跳转方向。此时，编译器需做出保守估计，认为所有可能的赋值都可能影响使用点。若 X 是程序输入，其值在编译时未知，编译器只能假设所有分支都可能执行。这种保守估计保证了优化的安全性，但可能导致优化不够激进。

**9.4.3数据流分析3**

通过深入研究程序特性并设计有效算法，可缩小静态分析与动态行为之间的差距。例如，若对程序稍作修改，增加新的赋值语句，静态分析可能显示 Y 的取值集合为 {2,3}，但实际运行时可能只为 2。这表明，通过精确分析程序特性，可使静态分析结果更接近期望。

总之，数据流分析旨在对程序代码进行静态分析，获取数据的保守信息。尽管静态分析结果通常不精确，但安全性至关重要。数据流分析是一大类分析方法而非单一算法，其具体类型取决于优化目标。接下来，将重点研究两种数据流分析算法：到达定义分析和活性分析，它们在程序优化中具有重要意义。

**9.5.1 到达定义分析简介**

到达定义分析（Reaching Definitions）是一种经典的数据流分析算法，常用于常量传播、死代码删除等优化。在研究此算法的过程中，需要掌握“定义与使用”这样的基本概念，以及数据流方程与不动点迭代求解等核心技术。

首先，所谓“定义”指的是对变量的赋值操作，而“使用”则指对变量的值进行读取。在源程序中，诸如 `y = 3`、`z = x + 1`、`A = z` 这样的语句，都分别包含对变量 y、z 和 A 的定义。与之对应的，当语句中出现 `a = y` 或 `if x > 0 goto L1 else L2` 时，就存在对变量 y 或 x 的使用。理解定义与使用的概念，是后续到达定义分析的基础。

考虑下面带编号的程序片段（语句前数字即编号）：

    1: y = 3
    2: z = y + 1
    3: if z > 0 goto 7 else 4
    4: y = 5
    5: x = y + 2
    6: … 
    7: a = y
    

在进行常量传播时，我们会询问“能否将第 7 条语句中的 y 替换为常数”。这等价于问：“哪些对 y 的定义可以到达语句 7？”换句话说，需要找出程序中每一个可能影响到第 7 行 y 值的赋值点。结合上例可知，只有编号 1 的定义可达语句 7，因此可将 y 替换为常数 3，从而完成一次常量传播优化。

到达定义分析的目标是：对程序中每个变量的使用点（如上例中语句 7 对 y 的使用），找出所有可能到达该点的定义。通过这个分析，可为后续的常量传播、死代码删除等优化提供精确的前提信息。

---

**9.5.2 生成集和杀死集的定义**

要形式化地描述到达定义分析，首先需为每条可能的定义语句 d 构造两个集合：产生集 gen[d] 与杀死集 kill[d]。

- **产生集 gen[d]**  
  对于定义语句 d，gen[d] 仅包含 d 自身，表示从该点开始，定义 d 能够向后传递。

- **杀死集 kill[d]**  
  若 d 定义了变量 x，则 kill[d] 包含程序中对 x 的所有其他定义，表示这些旧定义在越过 d 后不再可见。形式上
  
  kill[d:x]=defs[x]−{d}
  
  其中 defs[x] 表示程序中对 x 的所有定义点编号集合。

例如，在上例中，对变 量 y 的所有定义编号集合为 defs[y]={1,4}。因此

gen[4]={4},kill[4]={1}.

---

**9.5.3 基本块内的数据流方程**

在单条基本块（无分支、跳转，仅线性语句序列）中，可为每条语句 si​ 定义两个数据流集合：

- IN[si​]：在执行 si​ 之前可见的所有定义。

- OUT[si​]：在执行 si​ 之后可见的所有定义。

这两者满足如下方程：

IN[si​]OUT[si​]​=OUT[si−1​],=gen[si​]∪(IN[si​]−kill[si​]).​

其中对第一条语句，IN[s1​] 取空集。

以我们的例子为例，IN[1]=∅，OUT[1]={1}；接着 IN[2]={1}，OUT[2]={1,2}；……依次向下，便可计算出每个点的到达定义。

---

**9.5.4 数据流方程的直观意义**

之所以称上述等式为“数据流方程”，是因为它们既像线性代数中的方程组，又形象地描述了“定义信息”沿程序流图的流动过程：各个定义在基本块内部从前向后传播，同时在遇到新的定义时替代掉旧的定义。每个程序点的 IN 集合即是“流入”该点的所有定义，OUT 集合则是“流出”该点并可到达下游语句的定义。

---

**9.5.5 基本块内算法实现**

基于上面的方程，可在单个基本块内用一次顺序扫描完成到达定义分析。伪代码如下：

    function ReachingDefinitions(statements):
      set ← ∅
      for s in statements do
        IN[s]  ← set
        OUT[s] ← gen[s] ∪ (IN[s] − kill[s])
        set    ← OUT[s]
      end for
      return IN, OUT
    

这里 `statements` 为基本块内按顺序排列的语句列表，`set` 用来保存上一个语句的 OUT 集合。

---

**9.5.6 在一般控制流图上的推广**

对于含有分支与合并的控制流图（CFG），上述方程需做如下推广：令 pred(s) 为所有能直接跳转至 s 的前驱语句集合，则

IN[s]OUT[s]​=p∈pred(s)⋃​OUT[p],=gen[s]∪(IN[s]−kill[s]).​

---

**9.5.7 不动点迭代算法**

由于 CFG 中可能存在环路，上述方程通常通过不动点迭代求解。伪代码示例如下：

    initialize IN[s] = OUT[s] = ∅ for all statements s
    repeat
      changed ← false
      for each statement s in CFG do
        newIN  ← ⋃ OUT[p]  for p in pred(s)
        newOUT ← gen[s] ∪ (newIN − kill[s])
        if newIN ≠ IN[s] or newOUT ≠ OUT[s] then
          IN[s], OUT[s] ← newIN, newOUT
          changed ← true
        end if
      end for
    until not changed
    

该算法在每轮迭代中更新所有语句的 IN 和 OUT 集合，只要有任一集合发生变化就继续迭代，直至所有集合稳定为止，即达到不动点。

**9.5.8 示例与终止性**

取一个简单 CFG 包含环路的例子，可观察到在初始多轮迭代中，大多数集合会不断增长，直到循环带来的“新定义”不再涌入，所有集合达到稳定状态后算法终止。关于不动点算法为何一定能在有限步骤内终止，其证明可参照不动点理论，基于每个集合在迭代中单调递增且全局定义点有限，两者结合保证有限迭代后必达固定点，此处留作练习。

**9.6.1活性分析1**

在上一讲中，我们讨论了到达定义分析这一数据流分析算法。本讲将聚焦于另一类关键的程序分析算法 —— 活性分析。活性分析的核心动机源于寄存器分配优化的需求。在代码生成过程中，我们通常假设目标机器拥有无限数量的虚拟寄存器。这种假设极大简化了代码生成算法，因为无需考虑物理寄存器数量的限制。然而，现实中的物理机器寄存器数量是有限的，例如常见的 32、64 或 128 个。因此，在代码实际运行前，必须将无限的虚拟寄存器映射到有限的物理寄存器上。这一过程称为寄存器分配优化，而活性分析正是实现这一优化的基础。

寄存器分配优化的目标是将无限的虚拟寄存器映射到有限的物理寄存器中。为了实现这一目标，首先需要通过活性分析确定每个程序点上哪些变量是活跃的。活跃变量是指在当前程序点之后仍会被使用的变量，它们必须驻留在寄存器中以保证程序的正确执行。

**动机**

**活跃区间**

活性分析旨在确定程序中每个点上活跃的变量。活跃区间是指变量从定义到最后一次使用之间的范围。在上述示例中：

* 变量 A 的活跃区间从其定义到 B 的计算。

* **出集合（out）** ：表示语句执行后的活跃变量集合。
* **入集合（in）** ：表示语句执行前的活跃变量集合。

**数据流方程**

* `out[si ] = in[si+1 ]`
* `in[s] = gen[s] ∪ (out[s] - kill[s])`

**9.6.3活性分析3**

推广到整个控制流图，活性分析的数据流方程如下：

其中，`succ[s]` 表示基本块 s 的所有后继基本块。

活性分析的算法采用不动点算法，从空集开始迭代，直到所有集合不再变化。算法的终止性由变量数量有限保证，每次迭代集合严格增大，最终必然收敛。
