## 宏内核（Monolithic Kernel）
这种架构通常没有明确的结构划分，功能模块高度耦合。
- 定义: 操作系统的大量功能被组合到一个巨大的、单一的内核程序中 。系统调用接口之下、物理硬件之上的所有东西都在内核里 。
- 书中的例子:
	- MS-DOS： 为了在有限空间内提供最多功能而设计，没有严格的模块划分 。应用程序可以直接访问底层I/O，导致一个错误的用户程序就可能让整个系统崩溃 。
	- 传统UNIX: 内核包含文件系统、CPU调度、内存管理等所有核心功能 。这种“单一式结构”使其难以增强和维护 。
- 优点:
    - 高性能: 因为功能模块都在同一地址空间，彼此通过简单的函数调用通信，效率很高。
- 缺点:
    - 难以维护: 代码库庞大复杂，牵一发而动全身 。
    - 稳定性差: 任何一个组件的错误都可能导致整个内核崩溃 。


## 分层方法 (Layered Approach)
- 定义: 操作系统被划分为若干层 。最底层是硬件，最高层是用户界面 。
- 核心原则: 任何一层只能调用其下一层所提供的功能和服务 。
- 优点:
    - 简化设计与调试: 可以从底层开始，逐层进行开发和验证。如果某一层出错，错误一定位于该层，因为其下各层都已调试完毕 。
    - 信息隐藏: 每一层向其上层隐藏了底层实现的细节 。
- 缺点:
    - 难以定义层次: 系统组件之间常有复杂的依赖关系，很难清晰地划分层次 。
    - 性能低下: 用户请求（系统调用）需要穿越多个层次，每一层都会增加额外的开销，导致执行时间变长 。

## 微内核 (Microkernel)
- 定义: 将所有非基本的功能（如文件系统、设备驱动）从内核中移除，让它们作为用户空间的程序来运行 。
- 核心功能: 内核只保留最基本的服务，如进程管理、内存管理、通信机制 。
- 工作方式: 用户程序与系统服务之间通过内核提供的“消息传递”来进行通信 。
- 当一个程序需要文件服务时，它不会直接调用内核函数。它会向内核发送一个请求，内核再把这个消息转发给在用户空间运行的文件进程。处理完后，再通过内核将结果消息传回用户程序。
- 优点:
    - 易于扩展: 添加新服务只需在用户空间增加程序，无需修改内核 。
    - 高可靠性与安全性: 如果一个服务崩溃，它不会影响到内核或其他服务，整个系统依然可以运行 。
    - 可移植性好: 内核很小，将其移植到新的硬件平台更容易 。
- 缺点:
    - 性能问题: 用户空间和服务之间的频繁消息传递会产生较大的性能开销 。书中提到，Windows NT的早期版本就因此性能不佳，后续版本为了性能将更多组件移回了内核空间 。


## 模块化
- 核心思想：这是一种折中方案，试图结合宏内核的性能和微内核的灵活性与稳定性。
- 定义：内核本身只包含一组最核心的组件（如CPU调度、进程间通信等），而其他功能服务（如文件系统、设备驱动、系统调用）则作为独立的模块存在。这些模块可以在系统启动时或运行时被动态地加载到内核中，也可以在不需要时被卸载 。
-  模块化方法的优势
	- 与微内核的区别：微内核的服务运行在用户空间，与内核通信需要昂贵的“消息传递”。而模块一旦被加载，就运行在内核空间，与内核其他部分的通信是高效的直接函数调用，因此性能远高于微内核 。
	-  高性能：模块在内核空间内运行，通信效率与宏内核一样高 。
	- 更易于维护：相比于将所有代码都混在一起的宏内核，模块化的划分使得代码结构更清晰。
	- 更小的初始内核：内核本身可以保持相对精简，只在需要时加载相应功能。
