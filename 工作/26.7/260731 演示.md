### 2. 完成结构化条件到 SCL 的最小生成原型
完成了一个最小版本，可以读取结构化 JSON 文件中的允许条件、禁止条件和常用比较判断，并自动转换成 SCL 代码。
当前主要支持：
- 允许条件和禁止条件；
- AND、OR 逻辑；
- 布尔状态判断；
- 等于、不等于、大于、小于等常用比较。
示例输入文件：
```
tests/fixtures/scl_export/demo_categorization.json
```
首先进入原型所在目录：
```
cd /d/develop/project/Spec2Control/.worktrees/scl-tia-export
```
然后执行生成命令：
```
python src/scl_export.py \
  --input tests/fixtures/scl_export/demo_categorization.json \
  --output-dir data/scl-output/demo-process/chapter_2 \
  --block-name FB_S2C_DemoProcess
```
运行成功后，会生成以下两个主要文件：
```
data/scl-output/demo-process/chapter_2/FB_S2C_DemoProcess.scl
data/scl-output/demo-process/chapter_2/FB_S2C_DemoProcess.scl_report.json
```
其中：
- `.scl` 文件是自动生成的西门子 SCL 代码；
- `.scl_report.json` 是本次生成的检查报告。
当前完成的是最小原型，主要验证“结构化条件转换成 SCL”这条流程可以运行。定时器、复杂设备控制等内容暂时还没有纳入转换范围。

### 3. 完善 SCL 生成过程中的自动检查和失败保护

由于模型生成的 JSON 文件可能存在格式不完整、变量名称不符合 SCL 规则、数据类型前后不一致等问题，因此在 SCL 生成程序中加入了自动检查和保护。
当前主要检查以下内容：
- 输入文件格式是否符合要求；
- 变量名称是否符合 SCL 命名规则；
- 不同变量整理后是否出现名称重复；
- 变量属于 Bool 开关量还是 Real 数值量；
- 同一个变量是否存在数据类型冲突；
- 不同结果之间是否存在循环依赖；
这些检查已经集成在 SCL 生成过程中。执行第二部分的生成命令时，程序会自动完成检查：

```
读取JSON
    ↓
检查输入、名称、类型和逻辑关系
    ↓
检查通过
    ↓
保存正式SCL文件并生成PASS报告
```

检查报告位置为：

```
data/scl-output/demo-process/chapter_2/FB_S2C_DemoProcess.scl_report.json
```
报告中的：
```
"status": "PASS"
"errors": []
```
表示本次离线生成和内部检查通过。
为了验证这些检查功能是否能够正常工作，可以运行自动化测试：

```
python -m unittest tests.test_scl_export -v
```

该命令会使用正常输入和故意设置的错误输入，验证程序能否识别名称冲突、类型冲突、循环依赖以及文件清理等问题。这个测试命令是用于验证生成器本身，不是每次生成 SCL 前必须单独执行的操作。
