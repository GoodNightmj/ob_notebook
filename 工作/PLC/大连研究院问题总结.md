**问题 1：** 目前工业领域的 PLC 程序通常规模较大（约 4000-5000 行），而我们尝试将 PLC 语言转换为 FPGA 语言时，代码规模相对较小（约 100-200 行）。

**任务：** 为满足工业应用需求，需要使用大规模的 PLC 程序对我们的程序进行测试，确保其在真实工业环境下的可行性与可靠性。

  

**问题 2：** 出于要求，操作系统必须选择国产系统。但现有开源软 PLC 程序尚未适配国产操作系统。

**任务：** 针对 Sylix OS 和 XiU OS 等国产操作系统，对开源软 PLC 进行相应适配，以确保在国产操作系统环境下的正常运行和后续维护。

  

**问题 3：** 在 FPGA 上开发复杂功能模块（如计时器、计数器）时，因市面上其他产品并未开源此部分，仅提供输入输出描述，因此如何保障这些模块的可靠性和稳定性是一大挑战。

**任务 4：** 后续需对相关功能模块进行深入仿真测试，尽量覆盖边缘和异常情况；同时，需持续完善功能块的编写和验证工作。

  

**问题：** 最终目标是研发一款 PLC（而非工控机），这要求我们实现模拟量输入（Analog Input）和数字量输入（Digital Input）采集等功能。

**任务：** 为实现数据采集功能，计划使用单片机方案；黄路凡拥有相关嵌入式开发经验，可支持这一工作。

  

**问题 5：** 目前所研发的 PLC 属于单机 PLC，尚无法满足多机之间的协同控制需求。

**任务：** 实现 PLC 之间的通信，包括通信协议的选型、端口使用方式等，从而支持多机互联互通。

  

**问题 6：** 不同品牌 PLC 的编程语言在语法上存在差异。我们编写的“PLC 语言 -> FPGA 硬件语言”转换程序需要尽量兼容更多 PLC 品牌。

**任务：** 扩展和完善程序，以覆盖更多品牌和语法特性。但这项工作量较大，需要进行长期规划。

  

**问题 7：** 硬件 PLC 必须具备稳定性和安全性等核心特性。

**任务：** 在后续研发中，为 PLC 增加相关的安全机制与防护功能，预防数据丢失、系统宕机等潜在风险。

  

**问题 8：** 现有 IDE（PAL-PLC）功能尚不完善，仅支持从 IL 表到 Verilog 的转换。后续还需支持梯形图等其他 PLC 语言形式。

**任务：** 进一步开发和完善 IDE，为我们的转换程序提供更加完善、美观的图形化界面，以提升可用性与易用性。
